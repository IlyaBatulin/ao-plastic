Это техническая проверка и список вопросов для юриста,
не заключение о полном соответствии законодательству.
Основание: локальный исходный код и ограниченная проверка сервера.
На сервере HEAD 25e84a7; локальные изменения не развёрнуты. Хеши выбранных
файлов отличаются (возможны в том числе различия перевода строк).
Поэтому находки кода ниже нельзя без дополнительного сравнения считать
подтверждённым поведением production-сборки.

## Приоритетные замечания

| Приоритет | Наблюдение | Что нужно сделать |
| --- | --- | --- |
| До реального сбора ПД | Проверенный Supabase-проект находится в eu-west-1. Создание пустой БД в Москве ещё не означает локализацию | Перенести реальный поток записи/чтения, Auth и резервные копии; проверить production env; до этого тестировать на синтетических данных |
| Высокий | В components/cookie-consent-banner.tsx крестик вызывает handleAccept | Закрытие не должно записывать согласие; отдельно определить необходимые/необязательные cookies, блокировку внешних сервисов и отзыв выбора |
| Высокий | В регистрации раньше согласие подразумевалось из общей фразы; локально добавлен отдельный неотмеченный чекбокс | Проверить текст согласия для регистрации и фиксировать доказательство на сервере: версию, время и связь с субъектом; текущий чекбокс без журнала этого не решает |
| Высокий | API order/contact-messages/vacancy-responses/rfp-responses не содержит проверки и фиксации consent; UI-проверку можно обойти | Спроектировать доказуемую фиксацию согласия там, где оно основание: версия, цель, серверное время и связь с обращением; не собирать лишние данные для журнала |
| Высокий | В order/route.ts есть отправка имени/телефона/email в Telegram при настройке токена | Подтвердить реальную конфигурацию, правовое основание/трансграничную передачу; предпочтительно уведомлять только номером заказа и ссылкой на защищённую админку |
| Высокий | Политика считает продолжение использования сайта и другие общие действия согласием | Пересмотреть с юристом: политика информирует, согласие оформляется отдельно; договорные основания не смешивать с маркетинговыми |
| Средний | Согласие перечисляет имя/телефон/email и цель заключения договора; сайт также содержит регистрацию, заявки соискателей и другие формы | Сопоставить цели, перечни полей, сроки, основания и получателей по каждому сценарию |
| Средний | В исходном JSON политики есть незаполненные банковские реквизиты и универсальные формулировки | Сверить фактически отображаемые HTML/PDF: renderer может скрывать строки; не публиковать шаблонные поля. Банковские реквизиты не объявлять обязательным элементом самой политики |
| Перед публикацией | Серверная /legal/privacy-policy возвращает 307 на /login | Если через вход уже собираются ПД, обеспечить доступ к политике без входа; закрытый тестовый сайт не выдавать за доступную публичную политику |

Наличие пакета аналитики или домена в CSP не доказывает фактическую передачу.
Нужна отдельная сетевая проверка браузера до/после выбора cookies, включая карты,
видео, шрифты и аналитику. Из-за ограничения доступа полный live-аудит не завершён.

## Что невозможно подтвердить только исходниками

- Уведомление РКН и актуальность записи оператора, сведения о размещении БД.
- Договоры с обработчиками/хостером и реальное расположение копий.
- Ответственный за ПД, сроки хранения/удаления, обработка обращений и инцидентов.
- Основания и уведомления для внешних/трансграничных передач.
- Правомерность публикации фото и сведений о сотрудниках, лицензии на медиа.
- Действительность сертификатов и применимость обязательного раскрытия для АО.
- Модель продаж: только B2B-заявки либо также дистанционная розница.

Если есть розница: проверить оферту, продавца, свойства/цену товара, оплату,
доставку, возврат, претензии и применимость ККТ. Для формы запроса B2B нельзя
автоматически навязывать весь набор интернет-магазина; требуется ответ владельца.
Не публиковать выдуманные сроки возврата, условия оплаты или гарантии.
