# 🏠 Инструкция по добавлению хозяйственных товаров

## Порядок применения миграций

⚠️ **ВНИМАНИЕ**: Миграции нужно применять **СТРОГО** в следующем порядке!

### 1. ✅ Обновление схемы (ОБЯЗАТЕЛЬНО ПЕРВЫМ!)
```sql
\i migrations/011_update_products_schema_for_household.sql
```

**Что делает эта миграция:**
- Добавляет колонку `display_order` в таблицы `categories`, `subcategories`, `products` (для сортировки)
- Добавляет поля для хозяйственных товаров: `barcode`, `package_quantity`, `weight`, `dimensions`, `material`
- Создаёт индексы для быстрого поиска

❗ **Без этой миграции последующие миграции вызовут ошибку:** `column "display_order" does not exist`

### 2. Добавление категории и ведер/тазов
```sql
\i migrations/008_add_household_products.sql
```
Добавляет:
- Категорию "Хозяйственные товары"
- 7 подкатегорий
- Ведра (BASE 9,5л, 2,5л, 5л, 7л, 10л)
- Тазы (10л, 15л)

### 3. Добавление уборочного инвентаря и стеклоочистителей
```sql
\i migrations/009_add_household_products_part2.sql
```
Добавляет:
- Совки (BASE, ERGO, с резинкой, для мусора)
- Щетки-сметки
- Наборы (совок + щетка)
- Пылевыбивалка
- Стеклоочистители (3 вида)

### 4. Добавление санузла, кухни, вешалок, отдыха
```sql
\i migrations/010_add_household_products_part3.sql
```
Добавляет:
- Комплекты для туалета (3 вида)
- Мыльница
- Воронка, кружка, фильтр-сеточка
- Вешалки-плечики (5 видов)
- Веер для раздува огня

### 5. ⚡ Обновление фотографий товаров (опционально)

**Если вы уже применяли миграции 008-010 ранее** и получаете ошибку `duplicate key value violates unique constraint`, примените эту миграцию для обновления изображений:

```sql
\i migrations/012_update_household_product_images.sql
```

**Что делает эта миграция:**
- Обновляет пути к изображениям товаров (из `/placeholder.svg` в `/images/xoztov/...`)
- Добавляет артикулы в спецификации товаров
- Не создаёт новые записи, только обновляет существующие

**Когда использовать:**
- ✅ Если товары уже есть в базе и нужно обновить только фотографии
- ✅ Если вы повторно запускаете миграции
- ❌ НЕ нужна при первом запуске миграций 008-010

## Характеристики товаров

Каждый товар содержит:

### Основные поля:
- `name` — название товара
- `slug` — URL-дружественный идентификатор
- `description` — описание товара
- `specifications` — JSON с техническими характеристиками

### Новые поля для хозтоваров:
- `barcode` — штрихкод (4630002...)
- `package_quantity` — количество в упаковке (для заказа по коробкам)
- `weight` — вес изделия в граммах
- `dimensions` — размеры (текст)
- `material` — материал (Полипропилен, ПЭНД и т.д.)

## Единицы измерения и заказ

### Заказ по штукам
Пользователь выбирает количество единиц товара.

### Заказ по коробкам
Указано в поле `package_quantity`:
- Например, "Ведро 2,5 л" — 20 шт в упаковке
- При заказе 1 коробки = 20 ведер

## ⚠️ Возможные ошибки при миграции

### Ошибка 1: `column "display_order" does not exist`

**Текст ошибки:**
```
ERROR: 42703: column "display_order" of relation "categories" does not exist
```

**Причина:** Миграция 011 не была применена первой.

**Решение:** Обязательно примените миграцию 011 (`011_update_products_schema_for_household.sql`) **ПЕРЕД** миграциями 008, 009, 010.

---

### Ошибка 2: `null value in column "id" violates not-null constraint`

**Текст ошибки:**
```
ERROR: 23502: null value in column "id" of relation "products" violates not-null constraint
```

**Причина:** В вашей таблице `products` поле `id` имеет тип VARCHAR/TEXT (не автоинкремент), поэтому нужно явно указывать его значение при INSERT.

**Решение:** ✅ Эта ошибка УЖЕ ИСПРАВЛЕНА в миграциях 008, 009, 010. Теперь каждый INSERT-запрос включает явное указание `id` (используется значение из `slug`).
